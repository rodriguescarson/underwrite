Underwrite

The options agent that has to earn its own position size.

1 / 8
Problem

An agent's most dangerous output is a confident report that does not match the account.

  • Every trading agent in this field claims risk management. Almost none measure whether their own claims are true.
  • LLMs state probabilities that are not calibrated, then size trades from that confidence.
  • "Order placed" from a tool call is a claim, not a fact. Nothing checks it.
2 / 8
Solution

Propose → gate → act → audit → calibrate → size

StrategistGemini agent (Google ADK) whose only market access is Alpaca's MCP server, read-only tools. Proposes one defined-risk spread with a stated P(profit), or declines.
Second opinionA different model (Claude Sonnet 4.5, or an open-source model on Featherless) reviews the specific legs with the same read-only MCP tools and must agree; the desk records the more conservative P(profit). Vetoes are on the ledger.
GateDeterministic Python. Re-quotes every leg via alpaca-py, recomputes max loss, enforces 1% of equity, DTE 7–45, spread, open interest, one structure per underlying, six open at most.
Executorplace_option_order through the MCP server. The server's reply is the executor's claim, recorded verbatim.
AuditorAlpaca CLI, separate binary, separate HTTP client. Reconciles every claim. Claimed-filled-not-filled = silent failure.
Sizing0.25% of equity at the floor → 1% only after 10 resolved trades with ECE ≤ 0.15, Brier ≤ 0.25, 99% claim accuracy.

CLI

6 / 8
Business value

Calibration-gated sizing is the missing primitive for agentic brokerage.

  • Alpaca's own thesis is "agent-first brokerage". The first question any allocator asks an agent is: how do you know it does what it says?
  • Underwrite is that answer as infrastructure: ledger, two-channel reconciliation, calibration → risk budget. Strategy-agnostic.
  • Sells to prop desks running LLM agents, to fintechs on Alpaca's Broker API, and as a compliance artifact.
