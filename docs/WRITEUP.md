# Underwrite — one-page write-up

**Thesis.** An autonomous trading agent's most dangerous output is not a bad trade; it is a confident report that does not match the account. Underwrite is an options desk built around that fact: an LLM strategist proposes, a deterministic gate disposes, an executor acts through Alpaca's MCP server, and an independent auditor checks every claim through Alpaca's CLI. Position size is a function of the agent's *measured* calibration, not its stated confidence.

**AI logic.** The strategist is a Gemini agent (Google ADK) with Alpaca's MCP server as its only market access, filtered to read-only tools (`get_clock`, `get_account_info`, `get_all_positions`, `get_stock_snapshot`, `get_option_chain`, `get_option_snapshot`, `get_news`, …). Each cycle it researches one liquid underlying (SPY, QQQ, IWM, AAPL, MSFT, NVDA, AMZN, GOOGL, META, TSLA), pulls the chain inside a 7–45 DTE window, quotes the exact legs it intends, and returns one JSON proposal — a bull-put, bear-call, iron condor, or debit spread — with a stated probability that the structure closes profitably under the exit plan, and the tool outputs it cites. It never places an order. If it has no edge (p_profit < 0.55) it must decline.

**Risk gates (deterministic, no model).** Every leg is re-quoted through alpaca-py; the gate computes net credit and max loss itself and ignores the strategist's numbers except to log the discrepancy. Hard rules: max loss per structure ≤ 1% of equity; DTE 7–45; bid/ask ≤ 15% of mid (or ≤ $0.10); open interest ≥ 100; one structure per underlying, four open at most; allowlisted underlyings only. Sizing: contracts = risk budget ÷ verified max loss, where the budget is 0.25% of equity at the floor and 1% once calibration is earned; the floor never falls below one structure, because a desk that cannot trade can never earn calibration. Exits are mechanical: take profit at 50% of credit, stop at 2× credit, close at 2 DTE.

**Calibration — how size is earned.** From the ledger: (1) claim accuracy — of orders the executor reported placed/filled, how many the CLI confirmed with a consistent status; (2) silent failures — claimed filled, CLI says otherwise; (3) Brier score and expected calibration error of stated p_profit against realised win/loss over resolved structures. The 1% budget unlocks only when ≥10 structures have resolved with ECE ≤ 0.15, Brier ≤ 0.25, claim accuracy ≥ 99% and zero silent failures. The metric code is reused from Attest (standard definitions). During the hackathon window the desk stays at the floor — the honest state for an agent with fewer than ten resolved trades — and the report says so instead of hiding it.

**Alpaca infrastructure.** *MCP server* (`uvx alpaca-mcp-server`, stdio): the strategist's read tools and the executor's `place_option_order` (multi-leg, `order_class=mleg`, limit at mid ± $0.02, `position_intent` per leg). *CLI* (`alpaca account get`, `position list`, `order list --nested`, `order get`, `clock`, JSON output): the auditor's channel, run as a subprocess with the same paper keys and nothing shared with the MCP path. *alpaca-py*: the gate's independent quotes (`OptionHistoricalDataClient.get_option_snapshot`, `TradingClient.get_option_contract` for open interest). *Account*: a paper account created for this hackathon, reset to $100,000; account number and creation time are in the first ledger snapshot. Everything the desk does is an append-only JSONL ledger (`proposals`, `gate`, `orders`, `audits`, `outcomes`) and the published report is generated from it and nothing else.

**What the judges can verify.** The account number in the report matches the CLI; every order id appears in both an executor claim and a CLI audit; every gate decision lists its reasons in plain English; every proposal lists the MCP tool calls it made.
